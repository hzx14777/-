## 五、遇到的问题与解决方案

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | MySQL `--initialize-insecure` 报 `Can't create directory ... (OS errno 2)` | 安装路径含中文「考试平台2」，MySQL 无法处理非 ASCII 路径 | 整套运行时装到 `C:\yk-runtime` |
| 2 | 导入 `ry-cloud.sql` 报 `Unknown command '\"' at line 1155`，后续表未建 | Windows 下 mysql 客户端默认按 GBK 读脚本，汉字的 GBK 尾字节 0x5C 被当成转义反斜杠，把字符串提前截断 | 导入时加 `--default-character-set=utf8mb4` |
| 3 | Nacos 启动失败：`Table 'ry-config.config_info_aggr' doesn't exist` | 项目自带 `ry-config.sql` 只含部分表，缺 Nacos 2.4.3 需要的 `config_info_aggr/beta/tag` | 先导官方 `mysql-schema.sql` 建全表，再导项目 `ry-config.sql` 灌配置 |
| 4 | Nacos 端口变成 56973 而非 8848 | 端口被运行环境变量/占用影响，与网关约定不一致 | 启动参数显式加 `--server.port=8848` |
| 5 | 服务启动报 Redis 认证失败风险 | `application-common.yml` 要求密码 `ruoyi123`，本地 Redis 无密码 | `redis.conf` 追加 `requirepass ruoyi123` |
| 6 | auth 启动失败：`Port 9210 was already in use` | **9210 被 QQ 客户端占用** | auth 改用 9300；服务走 Nacos 发现，网关路由无需改动 |
| 7 | manage / practice / proctor 启动失败：`Failed to bind NettyServer on 0.0.0.0:20883` | Dubbo 默认端口 `-1` 自增，多个服务并发启动时抢占同一端口 | 启动参数显式指定 `--dubbo.protocol.port`（20913/20917/20919 等） |
| 8 | AI 服务启动失败：`dynamic-datasource can not find primary datasource` | Nacos 中 `ruoyi-exam-ai.yml` 内容为空，没有数据源 | 通过 Nacos 接口补写 datasource 配置后重启 |
| 9 | 本地 curl 访问 8848 返回 `502 upstream connect failed` | 系统设置了全局代理 `HTTP_PROXY=127.0.0.1:57008`，本地请求被代理转发 | 本地请求统一加 `--noproxy "*"` |
| 10 | GitHub `git clone --depth 1` 6 分钟只下 35MB | 跨境链路限速 | 改用 Gitee 镜像 `repository/archive/master.zip` |
| 11 | 直接 POST 登录返回 403「没有访问权限」 | 登录接口标注 `@ApiEncrypt`，必须携带 `encrypt-key` 头 | 用 Node 内置 crypto 复现前端方案：32 位随机 AES 密钥，RSA(PKCS1) 加密密钥放请求头，body 用 AES-256-ECB/PKCS7 加密 |
| 12 | 登录提示验证码错误 | 验证码为数学题图形，干扰线导致无法直接识别 | 从 Redis 读 `global:captcha_codes:<uuid>`（值为算式结果）后提交 |
| 13 | `POST /question` 返回 500：`Field 'create_user' doesn't have a default value` | 该接口走 `insertByBo`，未补创建人；`create_user` 列 NOT NULL 且无默认值 | 改用前端实际调用的 `POST /question/create`（内部用 `LoginHelper` 补 createUser） |
| 14 | 建试题报 `Invalid JSON text ... for column 'question.answer'` | `answer` 是 JSON 列，不是普通字符串 | 按题型传 JSON：客观题为 `{"rightKeys":["B"]}` |
| 15 | 开始考试报「已超过最晚入场时间」 | 考试 `start_time` 设为当天 00:00，超过 `late_minute` 窗口 | 调整考试开始时间为当前时间、放宽 `late_minute` |
| 16 | 统计页初始全为 0 | 统计基于预计算汇总表，每 10 分钟定时重算 | 调用 `POST /stat/exam/{id}/recalc` 手动重算 |

## 七、电脑重启后打不开：原因与修复

### 7.1 故障现象

电脑重启后浏览器访问 `http://127.0.0.1/` 报 `ERR_CONNECTION_REFUSED`，`http://127.0.0.1:8080` 与 Nacos 控制台同样无法访问。重新执行启动脚本后恢复，但**每次重启都会复现**。

实测基线：故障状态下 18 个监听点全部为 `DOWN`，`java.exe` 进程数为 0，3306/6379/8848/8080/80 均无 `LISTENING`。

### 7.2 根因定位

| # | 根因 | 判断依据 |
|---|---|---|
| 1 | **零持久化托管（主因）**：16 个进程全部靠手工脚本 `/min` 窗口或终端会话启动，未注册为 Windows 服务、无计划任务、无启动项 | `Get-Service` 中无任何 mysql/redis/nacos/ruoyi 服务；`Get-ScheduledTask` 无非微软任务；启动文件夹仅 `desktop.ini`；HKCU `Run` 键无相关项 |
| 2 | **进程随宿主会话被回收**：启动命令的父进程退出后，整棵子进程树被 Job Object 一并终止 | 同一批进程在启动脚本返回后数分钟内全部消失；`nacos.log`/`mysql-error.log` 中无任何 `Shutting down` 记录，属外部强制终止 |
| 3 | **端口变量污染**：环境变量 `SERVER__PORT` 被 Spring 宽松绑定映射为 `server.port`，覆盖 `--server.port` 参数 | Nacos 实际起在 `59089` 而非 `8848`，并因端口被占直接 `APPLICATION FAILED TO START` |
| 4 | **环境变量未持久化**：系统与用户环境变量中均无 `JAVA_HOME`，全部脚本依赖硬编码绝对路径 | `[Environment]::GetEnvironmentVariables()` 查询 `JAVA_HOME` 为空；`nacos/bin/startup.cmd` 依赖 `JAVA_HOME` 判断 |
| 5 | **残留 pid 与固定等待**：非正常关机后 `mysql-data\*.pid` 残留，且旧脚本用 `timeout /t 10` 固定等待、不校验端口 | `DESKTOP-EM642R7.pid` 在 MySQL 未运行时仍存在；MySQL 冷启动实测需 5–90 秒不等，固定 10 秒等待必然误判 |

配套的三个实现缺陷（均已修复）：

- **Redis 配置路径**：msys2 版 `redis-server.exe` 把参数当相对路径拼接，传绝对路径会得到 `当前目录/C:\...\redis.conf` 并报 `can't open config file`。
- **前端进程形态**：`cmd → npm → node` 三级链启动时，中间层退出会让 vite 收到 stdin 关闭信号而终止，表现为「刚打印 ready 就消失」。
- **HTTP 探针走代理**：`Invoke-WebRequest` 默认使用系统代理，本地回环请求被劫持，健康检查误报「不可达」。

### 7.3 已实施的修复

**1）统一控制脚本 `C:\yk-runtime\ykctl.ps1`**（start / stop / status / restart × all / infra / core / exam / front）

- 启动前清除 `SERVER__PORT` 与全部代理变量，并按小写对同名环境变量去重（否则 `Start-Process` 会抛「字典中的关键字重复」）
- 每步都用**端口就绪探针**轮询替代固定 `timeout`，幂等：已在监听的服务自动 `SKIP`
- MySQL 启动前清理残留 pid；Redis 用相对路径 `redis.conf`；前端直接用 `node` 运行 vite 入口
- `status` 同时做端口探针与 HTTP 探针，一次看清 18 个监听点

**2）开机自启**：`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\yk-platform-autostart.vbs`

登录后延迟 30 秒静默执行 `start all`。关键点在于它由 `explorer.exe`/`wscript.exe` 拉起，**不隶属任何终端会话的 Job**，因此不会随会话结束被回收（这正是旧方案失效的机制）。删除该文件即取消自启。

**3）持久化环境变量**：写入用户级 `JAVA_HOME` / `MAVEN_HOME`，消除换终端、换机器即失效的隐患。

**4）启停入口改造**：`start-all.bat` / `stop-all.bat` / `status.bat` 统一转调 `ykctl.ps1`，避免两套逻辑漂移。

> 说明：注册 Windows 服务与计划任务均需管理员权限（`Register-ScheduledTask` 返回「拒绝访问」，`sc`/`schtasks` 被策略禁用），因此自启通过启动文件夹实现——同样无需管理员权限，且由系统登录流程拉起，效果等价。

### 7.5 日常启停

```bat
oss-run\start-all.bat     :: 全量启动（MySQL/Redis/Nacos + 14 个微服务 + 前端）
oss-run\stop-all.bat      :: 全量停止
oss-run\status.bat        :: 查看 18 个监听点状态

:: 只起基础设施 / 只起核心 / 只起考试业务 / 只起前端
powershell -ExecutionPolicy Bypass -File C:\yk-runtime\ykctl.ps1 start infra
powershell -ExecutionPolicy Bypass -File C:\yk-runtime\ykctl.ps1 start core
powershell -ExecutionPolicy Bypass -File C:\yk-runtime\ykctl.ps1 start exam
powershell -ExecutionPolicy Bypass -File C:\yk-runtime\ykctl.ps1 start front
```

**启动顺序约束**：Nacos 必须先于微服务就绪，且**中途重启 Nacos 会让已连接的 Dubbo 客户端失联**，表现为登录返回「RPC异常」。若单独重启过 Nacos，必须连带重启全部微服务。
