# 电脑重启后平台无法打开 —— 排查与修复说明

> 2026-11-03 | 适用：警院智慧考试平台（砚考 exam-platform + yj-bff 改造版）

## 一、现象

重启电脑后打开 `http://127.0.0.1/yj/login`：
- 登录页能显示，但身份下拉框只剩兜底数据（如“陈立群 · …”显示不全）；
- 点“进入平台”无响应或报网络错误；
- `/yjapi` 请求返回 500，8090 端口无服务。

## 二、根本原因（按影响排序）

| # | 根因 | 证据 |
|---|------|------|
| 1 | **服务没有任何常驻机制**。前端 Vite 开发服务器和适配服务（8090）都是调试时在临时终端里手工启动的进程，Windows 重启后全部消失，也没有任何开机自启项 | 重启后 8090 无监听，`/yjapi` 代理 500 |
| 2 | **启动脚本依赖 PATH 里的 node/npm，但本机根本没有系统级 Node**。唯一的 node.exe 在 `C:\Users\24243\.workbuddy\binaries\node\versions\22.22.2-6\`，属于 WorkBuddy 私有运行时，只在我这个终端会话里被注入 PATH。双击 `start-demo.bat` 时 cmd 找不到 node，脚本闪退 | `where node` 在系统 PATH 下无结果；此前 `npm run dev` 报 exit 127（命令不存在） |
| 3 | **旧方案是“dev server + 跨进程代理”**：前端跑 Vite 开发服务器（需现场编译 1 万+ 模块，首开慢），`/yjapi` 依赖 Vite 代理转发到 8090，两个进程缺一个就 500 | 停掉任一进程即复现 |
| 4 | **启动方式本身不可靠**：`PowerShell Start-Process` 在本机因代理环境变量大小写重名（HTTPS_PROXY/https_proxy）直接抛异常；直接以 node.exe 作为计划任务动作会被系统以 CTRL_C（0xC000013A）结束 | 见 run-logs 与任务历史结果 |

结论：不是代码坏了，而是**运行方式无法在重启后重建**，且重建脚本在无 PATH 环境下必然失败。

## 三、修复内容

### 1. 架构改为“单进程单端口”（消除根因 3）
- 执行了 `vite build`，前端产物在 `exam-front/dist`（约 9 MB）；
- `yj-bff/server.js` 增加**同源静态托管**：一个 Node 进程同时提供
  - 页面与静态资源（含 SPA 路由回退 index.html、ETag 缓存）；
  - `/yjapi/*` 接口（剥前缀直连 API）；
- 端口：默认 80，被占用自动降级 8090；监听 `0.0.0.0`，局域网可直接访问；
- 不再需要 Vite、npm、跨进程代理，重启后只需拉起一个进程。

### 2. 启动脚本不再依赖 PATH（消除根因 2、4）
`oss-run/` 下的脚本全部自带 node 查找逻辑（系统 PATH → WorkBuddy 运行时目录 → Program Files → LocalAppData）：

| 文件 | 作用 |
|------|------|
| `start-platform.bat` | 一键启动：先探活 → 优先走计划任务 → 失败则最小化窗口降级启动 → 打开浏览器 |
| `stop-platform.bat` | 停止服务（同时停掉计划任务实例） |
| `build-front.bat` | 前端有代码改动后重新构建 dist |
| `install-autostart.bat` | 注册开机自启（内部调 register-task.ps1） |
| `remove-autostart.bat` | 取消开机自启 |
| `check-env.bat` | 一屏自检：node、文件、端口、健康、自启、日志 |
| `run-bff.cmd` | 实际拉起 node 的脚本（自解析 node、写日志） |

### 3. 开机自启：计划任务（消除根因 1）
- 任务名 `YJ-Exam-Platform`，**登录 Windows 时自动启动**，动作是
  `cmd.exe /c run-bff.cmd`（实测直接用 node.exe 会被系统 CTRL_C 杀掉，cmd 包装稳定且无窗口）；
- 无执行时长限制，进程意外退出后自动重试 3 次（间隔 1 分钟）；
- 服务自身也加了兜底：`uncaughtException/unhandledRejection` 记录到 `run-logs/service.log`，不会无声死掉。

### 4. 入口
- 桌面已放快捷方式 **警院智慧考试平台.url** → `http://127.0.0.1/yj/login`；
- 项目内也有 `oss-run/打开考试平台.url`。

## 四、重启后的日常使用

正常情况下**什么都不用做**：登录 Windows 后服务自动就绪，双击桌面图标即可进入。

手动操作：
- 手动启动：双击 `oss-run\start-platform.bat`
- 手动停止：双击 `oss-run\stop-platform.bat`
- 排查问题：双击 `oss-run\check-env.bat`
- 恢复初始演示数据：删除 `yj-bff\data\db.json` 后重启服务

访问地址：
- 本机 `http://127.0.0.1/yj/login`；局域网 `http://<本机IP>/yj/login`
- 若 80 被占用降级为 8090，则地址变为 `http://127.0.0.1:8090/yj/login`（启动器会自动识别并打开正确端口）

## 五、验证记录（本次修复已完成）

1. 无 node 的 PATH 环境（模拟重启后双击）：启动脚本自行定位到 `22.22.2-2\node.exe` 并成功拉起服务；
2. 计划任务托管：跨多个独立会话健康检查持续 200，不再随父进程退出而死亡；
3. `stop → start` 全流程：走计划任务分支，约 3 秒就绪；
4. 生产构建页面：登录页正常取到账号列表（张予安 · 数据警务学院 · 2023 级），登录后进入考试大厅，浏览器控制台 0 报错；
5. 端口占用降级：80 被占时自动改用 8090，启动器探测两个端口并打开正确地址。

## 六、遗留注意事项

- `dist` 是构建产物：**改了前端代码必须先跑 `build-front.bat`** 再重启服务，否则看到的还是旧页面；
- 开机自启依赖“登录后启动”，锁屏不注销的场景不受影响；若从未登录（纯服务器场景）需要改任务为“不管用户是否登录都运行”，那需要管理员权限与存密码，演示场景没必要；
- 砚考原 Java 微服务（8080 网关等）与本平台无关，不影响本平台启动；需要旧后台时另行按 `boot-*.bat` 启动 MySQL/Redis/Nacos/微服务。
