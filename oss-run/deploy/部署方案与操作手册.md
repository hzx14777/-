## 二、最终部署架构

```
浏览器
  │  HTTP :80
  ▼
nginx 1.24（Alibaba Cloud Linux 源）      ← gzip 压缩、静态长缓存、访问日志
  │  proxy_pass 127.0.0.1:8090
  ▼
Node 20 yj-bff（systemd: yj-exam）        ← 同一进程：静态页 + /yjapi 接口
  ├─ /opt/yj-exam/yj-bff/data/db.json     ← 唯一数据源（全量读写）
  └─ /opt/yj-exam/run-logs/service.log    ← 业务日志
```

**目录布局**（刻意保持与开发机一致的相对结构，服务才能自动找到 dist 与 run-logs）：

```
/opt/yj-exam/
├─ yj-bff/{server.js, engine.js, seed.js, data/db.json}
├─ exam-front-react/dist/{index.html, assets/*}
├─ yj.env                 # 运行时环境变量（600）
├─ run-logs/              # 业务日志
└─ backup/                # 每日数据备份
```

**关键决策与理由**

1. **前端在本机构建、只上传产物**：服务器没有 npm 依赖需求，省掉 `npm install`（约 200 MB）与构建耗时；构建产物 1.5 MB。
2. **nginx 反代而非 Node 直听 80**：首屏 JS gzip 后 1.48 MB → **470 KB**；静态资源 30 天缓存；日后挂证书只改 nginx。Node 因此可以跑在非特权端口 + 只监听回环，减少攻击面。
3. **systemd 而非 nohup/screen**：`Restart=always` + 开机自启，且日志进 journald 便于取证。
4. **不用 PM2 cluster / 多实例**：数据是「内存态 + 全文件覆盖写」，多进程会互相覆盖答卷，这是硬约束。

## 六、常见错误现象与排查

| 现象 | 根因 | 排查 / 解决 |
|---|---|---|
| `systemctl status` 反复 `activating (auto-restart)` | 端口绑定失败（EACCES / EADDRINUSE） | `journalctl -u yj-exam -n 50`；`ss -lntp \| grep 8090` |
| 服务 running 但 80 打不开 | `YJ_PORT=80` 被占时**代码会静默降级到 8090** | 日志搜「端口 80 被占用」；`ss -lntp` 确认真实端口 |
| 页面提示「前端产物缺失」 | `YJ_DIST` 目录不存在 / dist 未上传 | `ls /opt/yj-exam/exam-front-react/dist/index.html`（提示来自 server.js:705） |
| 白屏 + `/assets/*.js` 404 | dist 与 index.html 版本错配，或把站点挂到了子路径 | 重传整套 dist；**不要**把应用挂 `/yj/` 子路径，nginx 也不要 rewrite |
| 接口 404 但页面正常 | 反代把 `/yjapi` 剥掉了，或前端指向错误域名 | `/yjapi` 必须原样透传，由 Node 剥前缀 |
| 提交答卷 500 + 日志 EACCES | data 目录权限被改 | `chown -R yj:yj /opt/yj-exam` |
| 重启后题库回到初始 | `db.json` 丢了，seed 自动重建 | 从 `/opt/yj-exam/backup/` 恢复后重启 |
| 502 Bad Gateway（nginx） | Node 没起 / 监听地址不是 127.0.0.1 / SELinux 拦反代 | `curl 127.0.0.1:8090/api/v1/health`；开 Selinux 时 `setsebool -P httpd_can_network_connect 1` |
| 本机 curl 卡住 | 客户端有系统代理 | 加 `--noproxy "*"` |
| 上传文件报 `No such file` | Git Bash 把 `/tmp/x` 转成 Windows 路径 | `export MSYS2_ARG_CONV_EXCL='*'` |
| SSH 连不上 | 密码错 / 安全组 22 未放行 / fail2ban 封禁 | 控制台 VNC 登录看 `/var/log/secure` |
| 考试时间显示差 8 小时 | 服务器时区为 UTC | `timedatectl set-timezone Asia/Shanghai`（本机已是 CST，无需处理） |

## 七、必须处理的风险（按优先级）

1. **root 密码 `12345678Ww` + 22 端口对公网开放 = 高危**。上线当天就应改强密码，并优先改为密钥登录：
   ```bash
   # 本机生成密钥后
   ssh-copy-id root@8.134.60.240
   # 服务器 /etc/ssh/sshd_config: PasswordAuthentication no → systemctl restart sshd
   # 更彻底：安全组 22 只放行你所在网段
   ```
2. **HTTP 明文传输学生姓名、学号、成绩**。有域名后必须上 HTTPS（`certbot --nginx` 一条命令），未备案前至少限制访问源 IP。
3. **会话签名密钥硬编码**在 `yj-bff/server.js:18`（`yj-exam-platform-2026`）。公网可访问状态下，拿到源码即可伪造管理员令牌，建议改为读环境变量并设置随机值（需改代码后重发版）。
4. **单进程 + 单 JSON 文件**：不可多实例；`kill -9` 或断电时正在写的那次保存可能损坏文件。已有每日备份，但**建议加 5 分钟级增量或改用 MySQL** 才敢承认真实考试。
5. **无监控告警**：目前只有 systemd 自愈，进程「活着但卡死」无法发现。建议加 30 秒端口探活（可用阿里云云监控 + 站点监控）。
